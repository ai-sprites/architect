# 契约内容

从调用者要完成的动作写起，说明输入、返回结果与副作用。核对缺省、缺失、空值、类型、长度、单位、时区和标识含义，优先沿用当前项目规则。只列本接口真正涉及的字段和条件。

身份认证回答调用者是谁，授权回答能对哪个资源做什么。资源或租户标识来自哪里、在哪里核对访问权限应清楚；客户端传来的归属信息不能自动证明权限。

按实际协议区分成功、业务拒绝、输入错误、权限问题及系统失败，定义调用者应如何识别和恢复。保持稳定的机器可识别语义，面向用户的提示与内部诊断信息分开，不能泄露秘密。若项目使用 HTTP，检查方法与状态语义；已有特殊包装应先分析其消费者，不以安装实践为由整体重写。

明确同步结果还是已受理后的异步结果；流、文件、事件和无正文响应按各自含义说明，不塞进统一 JSON 结构。重试会产生副作用时说明重复请求的处理办法。

保留一份项目认可的契约来源。已有 OpenAPI、类型定义、RPC 描述或事件 schema 时更新其真实来源和有关例子，运行项目的契约检查；无需新增第二套格式。不存在机器契约时，简洁文字和可运行用例也可以先消除具体歧义。

延伸阅读：[HTTP 语义](https://www.rfc-editor.org/rfc/rfc9110.html)、[OpenAPI 官方规范](https://spec.openapis.org/oas/latest.html)。仅在对应协议或工具已适用时参考，并核对项目实际版本。
