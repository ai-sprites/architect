# 兼容与演进

比较的不只是字段是否增加或删除，还包括必填性、默认值、可空性、枚举范围、顺序、错误类型和副作用。新增枚举或“可选”返回字段也可能击中严格解析的旧客户端，要检查实际消费者。

独立发布的两端需要考虑旧调用者配新服务、新调用者配旧服务，以及缓存内容。先增加兼容能力，再切换消费者，最后在真实使用证据允许时移除旧行为；无需改变的项目不引入版本系统。说明破坏性变更和部署顺序，不能用“同时提交”掩盖发布差。

分页方案由数据特性决定：偏移适合有边界的跳页需求，但变动数据可能导致重复或遗漏；游标需要稳定排序与唯一收尾键，并明确筛选改变、非法游标和结果结束时的行为。不要把某种分页方式设为全局默认，也不要假设每个列表都需要总条数。

核对更新是否可安全重复、去重标识属于哪个操作与调用者、重复有效期是什么，以及处理成功但响应丢失后的行为。异步消息还需说明允许的重复、乱序、重放与消费失败，按实际交付语义写清，不承诺未证实的恰好一次。

验证选择真实使用组合：保留旧消费者样例，针对改动验证新旧输入输出、失败语义和重复调用。只改注释可以检查契约一致性，不必新建完整测试平台。未运行的组合明确列出，待定规则只限制依赖它们的实现。
