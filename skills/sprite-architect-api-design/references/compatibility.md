# 兼容与演进

修改已有接口、增加分页、重试/消息处理或两端分批发布时，先检查实际消费者和旧契约，再确定变化及验证组合。兼容不能只由新增字段或同次提交推断。

## 变更与发布顺序

1. 对照旧/新契约与实际消费者，检查字段增加/删除、必填性、默认值、可空性、类型与范围、枚举、顺序、状态/错误类型、副作用和权限语义。新增枚举或“可选”返回字段也可能破坏严格解析，需消费者证据。
2. 独立发布时分别考虑旧调用者配新服务、新调用者配旧服务，以及缓存数据、事件或排队任务的旧格式。共享契约与身份/信任边界使用同一权威来源，标明受影响仓库、服务及消费者，不以“同时提交”掩盖发布差。
3. 有变化时先增加兼容能力，再切换消费者，最后在真实使用证据允许时移除旧行为。说明破坏性变更、部署/迁移顺序、共存期间的权威数据/契约、退出或回退条件、负责人及数据损失风险；不用变化的系统不引入版本平台。
4. 持久、跨仓、迁移、难逆选择或已采用规则例外必须留可引用决定和实际来源。未确认语义写清影响和所需决定，只暂停依赖部分；不能把推荐当成已批准新规则。

## 分页

每个分页契约选择并明确游标或偏移方式。变动、较大或信息流集合优先采用不透明游标与稳定唯一排序；有边界的后台随机跳页或总数需求可支持偏移，但需说明并发变动造成重复/遗漏的行为。根据本次数据与用户需求取舍，不把某一种设为所有项目的默认，也不假设每个列表必须返回总条数。

写清 limit/上限与默认、排序与唯一收尾键、筛选条件、边界/结束、筛选改变、无效/过期游标、跨页数据变化和去重/遗漏影响；需要总数时说明其准确性与成本。已有项目已确认分页规范或用户指定规范优先；新设计的项目自有 HTTP 分页接口默认遵循上述游标/偏移选择与明确边界要求，实质偏离或兼容例外保留理由及兼容影响。

## 幂等、重试与消息

核对更新能否安全重复、去重键对应哪个动作/调用者/资源、有效期、相同键不同参数、并发重复，以及处理成功但响应丢失后的结果。说明实际超时、重试、退避/熔断/降级约束及何时不能自动重试，不声称未证明的事务边界。

异步消息明确允许的重复、乱序、重放、消费失败与恢复；根据实际交付语义描述去重与结果确认，不承诺未证实的恰好一次。作业/调度/取消涉及接口语义时说明请求受理、运行、完成、失败及取消是否真正生效，不能把受理当完成。

## 验证与交付

保留真实旧消费者样例，针对改动核对新旧输入输出、成功/失败和权限语义、重复调用、并发、分页边界及相关发布组合；运行项目现有契约 lint、生成校验或消费者检查，并检查契约来源与真实示例一致。只改注释可以核对契约一致性，不必新建完整测试平台。

交付变更范围、受影响提供者/消费者、兼容性证据、部署/迁移与回退顺序、已接受决定/未来规则、实际运行的组合与结果、未运行组合和未知项。真实重要风险说明触发、影响、证据或信息缺口、负责人及后续验证；快迭代不降低安全、隐私、数据损失或难逆选择标准，待定规则只限制依赖它的实现。
