# 接口设计

让提供方和消费方对同一行为形成可检查的约定。本实践可独立使用，适用于项目已有 HTTP、RPC、事件或内部接口；保留既有项目已确认协议/格式及用户指定规范。新设计的项目自有前后端 HTTP API 保留 REST、HTTP 状态、JSON 包装与例外、明确分页和权威 OpenAPI YAML 的默认专业规范，具体见参考。

## 工作顺序

1. 明确调用者要完成的已确认动作、产品范围、服务与数据/租户边界，查找权威契约、消费者、现有协议/版本、项目约定及决定来源；先核实真实行为，不能把工具格式当成业务要求。
2. 新增或细化契约必须读 [契约内容](references/contracts.md)，完成输入输出、副作用、身份授权、错误与恢复、协议和权威来源设计。修改已有接口、涉及分页、重试/消息或分批发布时必须读 [兼容与演进](references/compatibility.md)，核对真实消费者、演进顺序和验证组合。
3. 将受影响的资源/动作、字段条件、成功失败、同步/异步、重复请求、兼容与迁移规则写成可执行约定。新设计的项目自有前后端 HTTP API 默认采用 RESTful 资源/一致 URI 与方法、恰当 HTTP 状态、统一且文档化 JSON 包装及例外、明确分页、权威 OpenAPI YAML 同改同查。已有项目已确认协议/格式和用户指定规范优先；非 HTTP/第三方不套该默认，不因引入实践迁移既有 API。实质偏离/兼容例外记录范围、取舍与迁移影响。
4. 未知语义记录问题、来源、影响与所需决定，必须由用户选择的部分及时直接询问；推荐、未回复或“待确定”不等于批准。继续已确定部分，不能虚构后端能力、示例结果或消费者行为。
5. 更新现有权威契约及真实示例，运行项目适用契约检查和受影响兼容组合；新设计的自有 HTTP API 按默认创建权威 OpenAPI YAML，已有明确不同契约规范则沿用。其他没有机器契约的场景写清可核对的文字约定及可运行用例。交付实际约定、来源、影响、必要部署/迁移顺序、约束、检查结果和未验证项；持久、跨仓、迁移、难逆选择或项目规则例外保留可引用决定记录，不能只留聊天建议。
6. 核对当前契约与此前结论的替代关系，保存本次交接所需文件、示例与检查证据，提供真实路径与版本。可以沿用一份已有契约，不强建第二套格式，也不能以“文档按需”跳过本次契约成果。

## 独立使用时的边界

本实践可以更新本次授权的权威契约及检查用例，交付接口设计与验证；不会因此实现服务、安装业务依赖、搭建应用、执行数据库迁移、修改生产代码/生产配置或部署。不能自行改变已确认产品范围、用户行为或服务能力，不替其他角色补写其产物，读取远端资料不等于可写上游。

“继续”“交付”沿用当前接口任务，补足契约及检查；“有什么产物/成果”先说明真实交付与缺项，不以编码或原型替代。泛泛推进语句不扩大职责；已有明确跨工作/实现授权时沿用并分别说明契约与实现结果，不重复索取授权。

给人用白话，详略与任务和用户要求匹配；不能为缩短篇幅删掉必要专业内容与证据，也不强建空文档。

确实需要用户决定时，优先使用客户端已经提供且适用的结构化提问界面；没有则在当前对话直接提问，不能只写进文档。有可行方案时给两到三个互斥选项、各自影响及有依据的推荐，推荐在前，并说明为什么现在需要决定；缺少事实而非选择时自然询问。收到答案后再做依赖部分，把实际选择、决定者与来源写回有关说明。已有答案和授权直接沿用；建议、未回复和“待确定”不算同意。只暂停依赖答案的部分，其余继续，普通接口设计细节自行处理。

需求迭代先核对已有依据和本次变化，说明哪些工作、角色和旧产物受影响；只做受影响的部分，无须重新召集全部角色。交接指出哪些旧结论仍适用、哪些已替代或需要核对，未验证的旧结论不能冒充当前结果。

快迭代不降低范围归属、验收条件、安全、隐私、合规、数据损失保护、共享及外部契约、迁移和回退、昂贵或难逆决定的标准。与本次有关的重要风险要说明触发、影响、现有证据或未知项、负责人及后续检查；只暂停依赖关键答案的部分，不为理论风险凑清单。

需要留存或交接时，把结论与证据写入用户指定业务仓库/目录，或沿用项目位置；无约定时可用 `docs/artifacts/<feature-id>/contracts.md`。交付所属仓库、根目录相对路径、真实链接与版本。可选索引用 `kind: "contracts"` 和根目录相对 `path` 登记，附件单独列出，Markdown 链接相对文档；代码留原处，产物不放进本 Skill 目录。资料 host repo、版本和文件由用户指定或沿用项目明确约定，未提交或未推送如实说明；bridge 不替上游推送。

首次引入角色或实践时，整次接入只把未明确的资料 host repo 和产物 repo/目录合并询问一次，允许“暂无/稍后配置”并先完成接入；已指定角色、已答或已暂缓的项不重问，真正读取时再补必需版本、功能或文件。

已有资料索引随业务文档新建、更新、移动、改名或删除同步维护：使用相对索引的真实链接、简短用途说明，移除失效条目，只登记实际存在文件；外部资料引用权威来源与版本。没有现成索引不因此强建一套目录。

当前任务确需跨 Git 读取、固定版本、比较或导出留存时，复用已有 bridge；缺失或能力不足时，AI 按 [artifact-bridge README 与接入手册](https://github.com/ai-sprites/artifact-bridge)把同一明确版本的完整 Skill 补齐到当前客户端已有目录，保留自定义并告知用户，无需再单独确认安装。用户拒绝安装或权限、网络不足时说明限制，继续可独立部分。普通本地文件和纯角色安装不触发补齐。
