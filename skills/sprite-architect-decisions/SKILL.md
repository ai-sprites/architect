# 技术决定

把当前架构问题整理为有证据、可实施的选择。本实践可独立使用，不要求安装 Architect 或补齐固定技术档案；已有项目约定和用户选择优先，安装实践不会产生新的技术规范。

## 工作顺序

1. 明确架构问题、已确认用户行为、受影响系统与交付范围，读取项目规则、现有代码/配置、契约、技术说明、决定与实际运行证据；先解释现状和变化理由，不能先选工具再寻找理由。
2. 技术选型、迁移、跨仓或持久/难逆选择必须读 [决定与取舍](references/decisions.md)，完成约束、现状/目标、真实方案及决定分析；系统关系、质量与风险工作必须读 [边界与验证](references/boundaries.md)，完成相关边界、场景和检查。一次任务涉及两类时两份都读。
3. 对本次涉及的业务、产品、工程与政策上下文核实来源和影响；分清现有/新建/混合范围，不能混合不同仓库或部署单元的约束。已确认项目要求和实际接受的决定约束实现，观察、建议、排除项和未知项保持区别。
4. 保留现有做法能满足需要的部分；实质新选择给出证据和可行取舍，不能把检测到的技术或推荐当批准。需要用户作出的决定及时直接询问，记录实际答案和来源；只暂停依赖项，普通架构分析继续。
5. 交付结论、证据、适用范围、收益/成本、未来实现约束和验证结果。应用选型/迁移/多范围工作交付可引用技术说明；持久、跨仓、迁移、难逆选择或规则例外必须留决定记录。实质边界变化更新相关 C4，已确认质量目标记录条件与方法，多项重要失败场景完成集中风险说明。可合并现有文档，不能以“不强建文档”省掉这些内容；具体字段见两份参考。
6. 核对已完成、未确认、未验证及被替代内容，实际保存本次需要引用/交接的成果并交付路径与版本。小问题可以用短段落交齐结论、约束和检查，不额外创建整套架构文件。

## 独立使用时的边界

本实践产出架构分析、技术说明、决定及验证证据，不因此安装业务依赖、搭建应用、改生产代码、数据库结构/配置或部署，不授权执行迁移。不得自行改变已确认产品范围或用户行为，不能因其他角色缺失代写其成果；远端读取权限不代表上游写入授权。

“继续”“交付”沿用本次架构任务并补足本职成果；“有什么产物/成果”先报告真实完成度和缺项，不用原型或编码替代。泛泛推进语句不会扩展职责；用户已有明确跨工作/实施授权时沿用，分别说明架构成果与实际实施结果，不重复索取授权。

给人用白话，详略与任务和用户要求匹配；不能为缩短篇幅删掉必要专业内容与证据，也不强建空文档。

确实需要用户决定时，优先使用客户端已经提供且适用的结构化提问界面；没有则在当前对话直接提问，不能只写进文档。有可行方案时给两到三个互斥选项、各自影响及有依据的推荐，推荐在前，并说明为什么现在需要决定；缺少事实而非选择时自然询问。收到答案后再做依赖部分，把实际选择、决定者与来源写回有关说明。已有答案和授权直接沿用；建议、未回复和“待确定”不算同意。只暂停依赖答案的部分，其余继续，普通架构分析细节自行处理。

需求迭代先核对已有依据和本次变化，说明哪些工作、角色和旧产物受影响；只做受影响的部分，无须重新召集全部角色。交接指出哪些旧结论仍适用、哪些已替代或需要核对，未验证的旧结论不能冒充当前结果。

快迭代不降低范围归属、验收条件、安全、隐私、合规、数据损失保护、共享及外部契约、迁移和回退、昂贵或难逆决定的标准。与本次有关的重要风险要说明触发、影响、现有证据或未知项、负责人及后续检查；只暂停依赖关键答案的部分，不为理论风险凑清单。

需要留存或交接时，把结论与证据写入用户指定业务仓库/目录，或沿用项目位置；无约定时可用 `docs/artifacts/<feature-id>/architecture.md`。交付所属仓库、根目录相对路径、真实链接与版本。可选索引用 `kind: "architecture"` 和根目录相对 `path` 登记，附件单独列出，Markdown 链接相对文档；代码留原处，产物不放进本 Skill 目录。资料 host repo、版本和文件由用户指定或沿用项目明确约定，未提交或未推送如实说明；bridge 不替上游推送。

首次引入角色或实践时，整次接入只把未明确的资料 host repo 和产物 repo/目录合并询问一次，允许“暂无/稍后配置”并先完成接入；已指定角色、已答或已暂缓的项不重问，真正读取时再补必需版本、功能或文件。

已有资料索引随业务文档新建、更新、移动、改名或删除同步维护：使用相对索引的真实链接、简短用途说明，移除失效条目，只登记实际存在文件；外部资料引用权威来源与版本。没有现成索引不因此强建一套目录。

当前任务确需跨 Git 读取、固定版本、比较或导出留存时，复用已有 bridge；缺失或能力不足时，AI 按 [artifact-bridge README 与接入手册](https://github.com/ai-sprites/artifact-bridge)把同一明确版本的完整 Skill 补齐到当前客户端已有目录，保留自定义并告知用户，无需再单独确认安装。用户拒绝安装或权限、网络不足时说明限制，继续可独立部分。普通本地文件和纯角色安装不触发补齐。
