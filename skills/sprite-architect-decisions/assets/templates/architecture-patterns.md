## 必需的项目公共基线

以下规范默认适用于新设计的项目自有前后端 HTTP API。已有项目已确认的协议、格式和用户指定要求优先；安装本 Skill 不会让示例自动成为已接受的全项目规则，也不要求迁移既有 API。非 HTTP 和第三方接口沿用其实际契约。对适用规则的实质兼容例外或变更，需要 ADR 说明范围、取舍与迁移影响。

在本说明中写明共享规则适用的应用或服务。框架、库、构建和数据访问等具体选择由开发角色完成，相关理由沿用其实现说明或项目已有记录。

| 标识 | 领域 | 必需模式 | 项目决定或证据 |
|---|---|---|---|
| API-REST-001 | RESTful 边界 | 项目自有 HTTP API 以资源建模，使用一致 URI 和 HTTP 方法；前后端通信保留明确的 RESTful 契约。 | <资源与版本约定> |
| API-STATUS-001 | 请求结果 | HTTP 状态码是传输结果的权威表达。使用恰当的 `2xx`、`4xx` 和 `5xx`，不得用 `200` 返回失败请求并依赖正文标志表达失败。 | <状态与错误映射> |
| API-ENVELOPE-001 | JSON 正文 | 项目自有成功和错误正文使用一套文档化的 JSON 包装族。定义成功数据、稳定领域错误码与消息、可选详情、元信息及关联字段，不掩盖 HTTP 状态语义。记录无正文、文件、流、健康检查、webhook 和第三方响应的例外。 | <schema 或 OpenAPI 组件真实链接> |
| API-PAGE-001 | 分页 | 每个分页契约明确采用游标或偏移量。可变、大型或信息流集合优先使用不透明游标及稳定唯一顺序；只有有界集合、管理端随机跳页或总量统计等需求足以解释时才使用偏移量。定义条数限制、排序、筛选、边界，以及无效或过期游标的行为。 | <各契约的选择与理由> |
| API-OPENAPI-001 | 契约来源 | 维护一份权威 OpenAPI YAML。API 行为变化时同步更新路径、方法、参数、请求与响应 schema、状态码及示例，并运行项目 OpenAPI lint 或契约检查。 | <YAML 真实路径与检查命令> |

## 关注点提示

- **API：** 契约归属、资源与版本规则、状态和错误映射、响应包装、分页及 OpenAPI。
- **数据：** 系统记录源、写入与事务边界、迁移、一致性、缓存和保留策略。
- **集成：** 同步或异步交互、超时、重试、幂等、失败处理和契约转换。
- **安全：** 身份传递、服务端授权、信任边界、秘密及敏感数据处理。
- **可观测性：** 结构化日志、指标、适用时的追踪、关联标识、脱敏及可见失败信号。
- **前端：** 影响系统结构的渲染要求、客户端与服务端的数据/状态归属、缓存一致性、设计系统边界及兼容。
